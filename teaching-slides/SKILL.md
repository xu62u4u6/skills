# 教學投影片與講稿

用同一個具體例子，讓觀眾看見對象如何改變、為什麼需要這個方法，再補名稱與公式。產出要能支撐使用者實際講清楚。

本 skill 記錄使用者的教學與設計偏好，適用於 Claude 與 Codex，不依賴特定工具名稱。當前明確要求優先；不把單次數值、頁數或美術選擇推廣成固定模板。

## 開工與修改範圍

- 先辨識目標檔案與版本、受眾已知內容、當頁問題，以及使用者要看提案、候選或正式成品。已有資訊就直接沿用。
- 回看相關對話與已認可的圖，找出使用者是靠哪個例子理解；從那裡延伸。
- 在工作中維持簡短的累積需求清單，包含之前確認的內容、圖、排版、符號與頁序。每輪逐項檢查，回報本輪結果與尚未滿足的項目；不要只實現最新一句要求。
- 大量刪頁、合併、重排前，先展示現況與具體提案。若使用者已核准範圍，直接完成；指定單頁小修也直接做，不重複請求批准。
- 使用者要求逐項確認時，一次交付一個可判斷的單位：通常一頁或一組緊密相關的對照頁，搭配短講稿與實際畫面。候選確認後才換入正式版；已明確要求更新正式版時直接執行。

## 概念：沿著已理解的例子增加一件事

1. 先提出問題，展示直覺做法遇到的真實限制，再引入方法。頁與頁之間要有理由，讓觀眾知道為何需要下一頁。
2. 先具體操作，再命名。例如先看雜訊像素 2、原圖像素 5，算出差值 3，再說明此範例中速度的定義。不要用尚未定義的「向量場、往哪裡走」開場。
3. 沿用同一個數值、影像或函數；需要變化時先改一個條件。每個教學步驟只新增一個主要概念，避免同時更換例子與表示方式。
4. 先定義角色與符號：現在是訓練或生成？哪些值已知？輸入、預測、目標各是什麼？時間、比例與步長有何意義？模型呼叫、樣本更新與權重更新須清楚區分。
5. 直覺與可追蹤的計算在前，公式作精確參考。公式可以保留，但不能代替說明。簡化仍須保留方法的實際差異；重要條件放在主圖或主文，避免主文造成錯誤印象後再靠小字補救。
6. 比喻須對得回實際對象與操作，簡短使用後回到原圖。若使用者更混亂，撤回比喻，改成實際數值、圖或表；不要疊加另一個比喻。

若正在帶使用者學習，先說明一個實驗要驗證什麼，讓他預測或嘗試，再解釋結果；一次只問一題。不能把「我懂了」、參考答案或程式通過直接當作已理解的證據。單純製作投影片時，不額外插入教學測驗。

## 圖：讓對象、操作與變化可見

- 圖是解釋工具：像素運算用像素格，影像外觀變化用可辨識影像。抽象方塊、點雲和箭頭須有明確對應，不能只放一串節點代表已解釋過程。
- 有圖的頁面與講稿先交代讀法：每格、顏色、座標、線、參數、起終點代表什麼，再講圖要回答的問題。
- 比較方法時固定可比較的部分：同一例子、尺度、圖大小、標記及位置。只改比較項目；方法真的不同的混合規則、時間方向、目標或生成流程必須呈現。
- 數字與文字就地對應。輸入 x、目標 y 靠近各自小圖；相減就直接畫出兩個對象相減；關係標在連線上，避免跨區找圖例。
- 訓練圖分清已知答案與模型預測；生成圖分清起點、模型輸出與更新後狀態。示範假設與實測結果要可辨識，不把預先知道的終點畫成生成時可取得的輸入。
- 總覽、時間軸或方法地圖要呈現真正關係：節點有具體小示意，連線說明改了什麼、解決什麼或付出什麼代價。概念承接與歷史因果須分清，不為故事順暢捏造演進。
- 前沿內容精選並接在相關分支；需要時可展開。篇數由當前需求決定，不把過去的「只留兩篇」變成永久上限。

## 排版：少框線、清楚對齊、保留有效密度

- 一頁回答一個主問題；所有圖文都服務它。整份簡報有主軸，章節能對回主軸。
- 減少無作用的外框、卡片與重複容器，優先用對齊、間距和必要分隔組織。保留有實際分組、狀態或操作意義的框線。
- 同級標籤等高、同角色圖像尺寸一致；對照頁維持可比較的布局與標題。箭頭不能穿過字，底部內容不能壓住頁碼或來源。
- 布局服從閱讀與操作順序。左右圖文、上下步驟、表格都可使用，不固定每頁同一版型。
- 壓頁數先刪重複、合併相關結論、移出進階細節或口語段落；不要用縮小字體、主圖或塞滿版面換取頁數。
- 來源可放底部較小字，但須可讀；主要限制與差異不能藏在註腳。保留頁碼與導覽空間。
- 沿用有效的既有設計。沒有證據支持固定字體、配色或美術流派；不要把一次認可推成永久風格。純色、少框線是傾向，仍以理解為準。不用 emoji 或無資訊的裝飾。

## 文字：每句提供新資訊

- 標題直接說內容或操作，例如「訓練 Diffusion：預測雜訊」。避免空泛標語與不幫助理解的分類包裝。
- 刪除同義重述、AI 腔、裝飾性核心句及附近已有的資訊。圖上已能清楚表達的內容，不再補一段描述同一件事。
- 投影片保留關鍵資訊；長引言、過場、逐步口語解釋與預想問答放逐頁講稿。講稿與投影片分開，頁面仍須具備讀圖所需標籤。
- 優先正面、直接陳述。少用「不是……而是……」、泛泛保險字句與卸責句；需要的條件、限制、來源及驗證狀態用具體事實或欄位交代，不得刪掉實質不確定性。
- 同一資訊集中在合適位置；回顧用短提示。術語與符號前後一致，縮寫首次出現時定義。
- 不把製作指令、受眾設定、設計意圖或「本文件先……接著……」寫進投影片。

## 報告與講稿：講得順，讓結論有依據

- 講稿順序以「如何讀圖 → 發生什麼 → 為何如此 → 本頁結論 → 下一個問題」為參考，按內容調整，避免每頁硬套相同措辭。
- 每段留下能記住的核心結論，必須濃縮剛剛展示的證據或操作，不能只加一句口號。
- 論文精選並講透：研究問題、具體改變、對應圖與結果、適用條件。作者、年份和方法名單不應擠掉主要解釋。
- 概念教學留在方法主線；能套用到聽眾專案的實驗設計收在比較與應用；較長問答放講稿或附錄。仍服從使用者指定的章節安排。
- 區分論文實際結果、教學示範與我們提出的實驗建議。這是編輯與證據呈現準則，不能把推論寫成使用者已說過的偏好或論文已驗證的結論。
- 報告已完成事項時附對應成果與檢查範圍；不要把局部畫面通過說成整份內容或研究數字都驗證過。

## 每輪驗收

1. 概念：能否指出本頁唯一主問題？新名詞有沒有接到已知例子？符號、數值、訓練與生成角色是否正確？
2. 圖文：觀眾是否知道怎麼讀圖？文字與數值能否就地找到？對照頁是否一致且保留真實差異？
3. 刪減：拿掉某句文字、框或裝飾會降低理解嗎？不會就優先刪除。縮頁不得犧牲主圖與字體可讀性。
4. 實際檢查：有預覽環境就渲染並親自查看截圖，檢查投影尺寸、頁碼、長字與遮擋；有互動就操作翻頁及相關控制。支援手機時也驗證手機。只產出截圖或編譯通過不算完成視覺審查。
5. 使用者既有要求是每輪投影片修改後分別取得學生與工程師 agent 審核：學生檢查讀圖與概念跳躍；工程師檢查數學、符號、方法差異與實作。修正後重審相關問題。有可用委派能力時執行；沒有時明確說明未完成獨立審核，不把自身檢查冒充獨立通過。

交付保持簡短：可查看的成品或截圖、本輪改變、驗證結果與必要限制。逐項修改時只保留一個下一步，不擴張成未授權的整份改版。
